## Native acceptance boundary

The native changes preserve existing seed records when initialization markers disappear, reject replacement of a different saved seed and retain malformed PIN records as unavailable. Backup, export and exit-funding authorization is tied to the current native read lease and action target. These are application-level controls. The native SDK connection still uses its own internal signer; no hardware key isolation or comprehensive native signing authorization is asserted.

Source-specific details and verification are recorded in [initialization preservation](native-initialization-preservation-20261027.md), [seed-write reconstruction](native-seed-write-reconstruction-20261027.md), [PIN policy/read lease](native-read-lease-20261027.md) and [PIN-policy consumers](native-pin-policy-consumers-20261027.md). Their test counts overlap and must not be added into an invented combined total.

## Release decision

The production interlock and unsupported-route containment remain in place. A successful package build or green CI does not close the missing execution/recovery contracts, physical-device checks or independent review. The final PR evidence must identify the exact application head, SDK package, source patch, workflow runs and accepted boundaries before a release decision is made.
